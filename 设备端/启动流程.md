# 车-机协同末端配送 · 小车端启动流程
> 一页纸操作手册 ｜ 2026-10-04

---

## 一、启动（一条命令）

```bash
bash ~/chen_car_drone/小车/start_car.sh
```

等它跑完 6 步，看到 **`✅ 全部启动完成 —— 现在等平台/前端下发指令即可`** 就算好了。

脚本自动按顺序做这些事（每步都等"就绪"才往下走）：

| 步骤 | 内容 |
|---|---|
| [1/6] | roscore（ROS 总控） |
| [2/6] | 导航（底盘 + 雷达 + amcl 定位 + move_base） |
| [3/6] | **关节状态单位转换**（度 → 弧度，MoveIt 必需） |
| [4/6] | 机械臂（MoveIt + 执行节点 + moveit_pose + 视觉） |
| [5/6] | 自动下发 AMCL 初始位姿（免手动点 RViz） |
| [6/6] | MQTT 桥接节点（连云平台，真跑模式） |

**可选参数**：
```bash
bash ~/chen_car_drone/小车/start_car.sh --rviz    # 带 RViz（调试、看地图）
bash ~/chen_car_drone/小车/start_car.sh --dry     # 干跑（不真导航，只验证链路）
```

## 三、发指令（让车干活）

### 方式 A：服务器上手动发（快速测试）

```bash
# 在【服务器】上
mosquitto_pub -h 127.0.0.1 -p 1884 -u cjy-car -P '<小车密码>' \
  -t cjy/car-01/cmd \
  -m '{"cmd":"goto_pick","task_id":"T0001","site":"1","slot":"1A","count":1}'
```

### 方式 B：走完整协同流程（NX 无人机端参与，★ 推荐）

```bash
# 在【NX】上
bash run_drone.sh slot 1              # 无人机问库位 → 平台分配
bash run_drone.sh drop 1 1A 2         # 无人机投放完成 → 平台自动派单给小车
```
→ ★ 之后小车**全自动**跑：导航取货 → 机械臂抓取 → 送达 → 上报 ✓

## ★ 启动顺序的原理（为什么不能乱）

```
roscore（总控）
   ↓
导航（底盘+雷达）── 底盘驱动 wd_base_control 在这里启动
   ↓                它发布的关节状态是【度】
单位转换 ───────── 把【度】转成【弧度】，改名后以 /joint_states 给 MoveIt
   ↓
机械臂（MoveIt）── 读 /joint_states（弧度）→ 才能规划 ✓
   ↓
初始位姿 ──────── 告诉 amcl"车在哪"，否则定位不对，导航必失败
   ↓
桥接节点 ──────── 连上云平台，等指令
```
★ **单位转换必须排在机械臂之前**（否则 MoveIt 一起来就报"invalid start state"）✓

## ★ 两个坑（踩过的，记下来）

1. **Windows 换行符**：脚本传 Linux 前必须转成 LF，否则报 `$'\r': command not found`
2. **roslaunch 的 remap 穿不透嵌套的 include**：
   - 在 `demo.launch` 外层加 remap 无效（因为 move_group 是更内层 include 起的）
   - → 所以要把 remap 加到**直接起节点的那个 launch**（`base_control.launch`）✓
