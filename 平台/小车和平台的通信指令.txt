小车 ⇄ 平台 走 MQTT（broker <你的服务器IP>:1884）
    ★ 小车发到： cjy/car-01/report      ← 上报（车 → 平台）
    ★★ 平台发到： cjy/car-01/cmd        ← 指令（平台 → 车）
    ★★★ 另外： cjy/broadcast            ← 广播（如货位变化，所有设备都收）
    命名规则：cjy/<设备号>/report 和 cjy/<设备号>/cmd ✓




    二、小车 → 平台：11 种上报（代码里 report() 的全部）

    #: 1
    event: position
    什么时候发: 每 10 秒
    带什么: x, y, yaw
    平台拿它干什么: 地图上画车的位置（quiet：不刷日志 ✓）
    ────────────────────────────────────────
    #: 2
    event: battery
    什么时候发: 定期
    带什么: percent, voltage, name
    平台拿它干什么: 电量显示
    ────────────────────────────────────────
    #: 3
    event: idle
    什么时候发: 启动时 / 任务结束 / 回到待命点
    带什么: note（bridge started / back_to_pick / back_home）
    平台拿它干什么: ★ 告诉平台"我空闲，可以派单"
    ────────────────────────────────────────
    #: 4
    event: arrived
    什么时候发: 到达取货点
    带什么: task_id, site
    平台拿它干什么: 车到了 → 等"货入库"
    ────────────────────────────────────────
    #: 5
    event: car_load
    什么时候发: ★ 夹住货并收回后
    带什么: task_id, slot, count, marker_id（读到的 AR 码号）, tracking_no
    平台拿它干什么: ★ 平台登记"货已装车"，并核对码号
    ────────────────────────────────────────
    #: 6
    event: pick_done
    什么时候发: 取货动作完成
    带什么: task_id, slot, count
    平台拿它干什么: 平台 → 发 deliver
    ────────────────────────────────────────
    #: 7
    event: car_depart
    什么时候发: 开始去送达点
    带什么: task_id
    平台拿它干什么: 界面显示"配送中"
    ────────────────────────────────────────
    #: 8
    event: dst_arrive
    什么时候发: 到达送达点
    带什么: task_id
    平台拿它干什么: 记录
    ────────────────────────────────────────
    #: 9
    event: shelf_place
    什么时候发: ★ 放入货柜
    带什么: task_id, dst, shelf_no
    平台拿它干什么: ★ 平台分配【配送点货柜】+ 状态置 PLACED（就是修好死循环那处 ✓）
    ────────────────────────────────────────
    #: 10
    event: delivered
    什么时候发: 放完货
    带什么: task_id
    平台拿它干什么: 状态置"已送达"
    ────────────────────────────────────────
    #: 11
    event: exception
    什么时候发: 出问题
    带什么: reason（没读到码 / 导航失败 / 未知站点 / 抓取异常）
    平台拿它干什么: ★ 平台上报警 ✓



    三、平台 → 小车：5 种指令

    #: 1
    cmd: goto_pick
    意思: 派单去取货点
    带什么字段: task_id, site, slot, count, dst, ★marker_id（期望的 AR 码）
    车怎么反应: 导航到取货点 → 到了上报 arrived
    ────────────────────────────────────────
    #: 2
    cmd: wait
    意思: 货还没入库，原地等
    带什么字段: site / task_id, reason
    车怎么反应: ★ 不动机械臂（防抓空气 ✓）
    ────────────────────────────────────────
    #: 3
    cmd: pick
    意思: 货已入库，开始抓
    带什么字段: task_id, slot
    车怎么反应: ★★ 这时才动机械臂：init→sentry→等码→校验→抓
    ────────────────────────────────────────
    #: 4
    cmd: deliver
    意思: 取完了，去送达点
    带什么字段: task_id, count, dst
    车怎么反应: 导航到送达点 → 摆姿态 → 松爪
    ────────────────────────────────────────
    #: 5
    cmd: go_home
    意思: 返回起始点（网页手动）
    带什么字段: x, y, yaw（可选，不给就用 HOME_POS）
    车怎么反应: 导航回起点

    ★ 另有 cjy/broadcast：平台广播（如 slot_update 货位变化 ✓）



    四、一次完整任务的时序（就是你刚才那次真实日志 ✓）


    小车（终端6）                          平台
       │ ① idle(note=bridge started) ────►  平台知道车在线了
       │ ◄──── ② goto_pick(… marker_id:3)    有单了 → 派车
       │ ③ 导航到取货点
       │ ④ arrived ────────────────────►   车到了（平台此时才查"货入库没"）
       │ ◄──── ⑤ pick                        确认入库 → 允许抓
       │ ⑥ 机械臂：init → sentry → 等AR码 → init → grap → 合爪 → init（夹住）
       │ ⑦ car_load(marker_id:3) ──────►   ★ 登记装车（记下读到的码号）
       │ ⑧ pick_done ──────────────────►
       │ ◄──── ⑨ deliver
       │ ⑩ car_depart ─────────────────►   界面显示"配送中"
       │ ⑪ 导航到送达点
       │ ⑫ dst_arrive ─────────────────►
       │ ⑬ 机械臂：grap（夹爪保持）→ 松爪 → init
       │ ⑭ shelf_place ────────────────►   ★ 平台分配配送点货柜 → 置 PLACED
       │ ⑮ delivered ──────────────────►
       │ ⑯ idle ───────────────────────►   平台知道可接下一单
       │ ⑰ ★ 自动回取货点（本地行为，不需要平台下指令）
       │ ⑱ idle(note=back_to_pick) ────►   回到待命点


    ★ 关键设计点（答辩可以讲）：

    ① goto_pick 里带【期望 AR 码号】→ 车抓前核对 → 不符不抓 + 告警 ✓ 防调包
    ② arrived 之后【不立刻抓】→ 等平台发 pick（确认货真在架上）→ 防抓空气 ✓
    ③ shelf_place 上报后平台【分配配送点货柜】→ 用户凭取件码自取 ✓
    ④ 位置/电量用 quiet 上报 → 不刷日志 ✓
